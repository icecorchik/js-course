1. Чем обращение obj.key отличается от obj[key]?
1. 
Оба варианта позволяют обращаться к свойствам объекта, но работают немного по-разному.
Через точку:
const product = {
    name: 'Мышь',
    price: 790
};
console.log(product.name);
JavaScript ищет свойство с буквальным именем name.
Через квадратные скобки:
const field = 'price';
console.log(product[field]);
JavaScript сначала получает значение переменной field, а затем использует его как имя свойства.
Результат — 790.

Главное различие:
product.field - Ищет свойство с именем field.
product[field] - Ищет свойство, имя которого записано в переменной field, то есть price.

Квадратные скобки также позволяют обращаться к свойствам с пробелами:
const user = {
    'user name': 'Анна'
};
console.log(user['user name']);
Через точку к такому имени обратиться нельзя.
Ответ: точка используется для обращения к свойству с известным именем, квадратные скобки позволяют использовать переменную или произвольное выражение в качестве имени свойства.




2. Как определяется значение this при вызове метода? Почему this теряется при передаче метода в переменную?
this обычной функции определяется способом её вызова.

Например:
const product = {
    name: 'Мышь',
    describe() {
        console.log(this.name);
    }
};
product.describe();
Здесь this указывает на product, потому что метод вызван через этот объект.
Теперь:
const describe = product.describe;
describe();
В этом случае функция вызывается отдельно от объекта.
Она больше не вызывается как product.describe(), поэтому в строгом режиме this равен undefined.
При обращении к this.name возникает ошибка.
Исправить это можно с помощью bind():
const describe = product.describe.bind(product);
describe();
Теперь this навсегда привязан к product для созданной функции.
Ответ: this определяется объектом, через который вызывается метод. Когда метод передают в переменную, связь с объектом теряется. Для исправления используют bind(), который создаёт новую функцию с привязанным значением this.




3. Чем this в стрелочной функции отличается от this в обычной?
У обычной функции собственное значение this, которое определяется при вызове.
У стрелочной функции собственного this нет. Она использует this из окружающего кода.
Пример:
const shop = {
    name: 'Мини-магазин',
    print() {
        const show = () => {
            console.log(this.name);
        };
        show();
    }
};
shop.print();

Результат:
Мини-магазин

Почему?
1. Метод print() вызван через shop.
2. Поэтому внутри print() значение this равно shop.
3. Стрелочная функция show не создаёт собственный this.
4. Она использует значение this из окружающего метода.
Ответ: обычная функция получает this в момент вызова, а стрелочная функция не имеет собственного this и использует его из внешней области.




4. Что такое поверхностная копия? Почему изменение вложенного объекта в копии видно в оригинале?
Поверхностная копия — это копирование объекта, при котором создаётся новый внешний объект, но вложенные объекты не копируются полностью.
Пример:
const original = {
    name: 'Клавиатура',
    dimensions: {
        width: 44
    }
};
const copy = { ...original };
Создаётся новый объект copy.
Однако original.dimensions и copy.dimensions ссылаются на один объект.
Проверим:
console.log(original === copy);
console.log(original.dimensions === copy.dimensions);
Результат:
false
true
Основные объекты разные, но вложенный объект общий.
Поэтому:
copy.dimensions.width = 50;
Изменит ширину и в original.
Аналогично работает Object.assign().
Для создания глубоких копий данных можно использовать:
const deepCopy = structuredClone(original);
Тогда вложенные объекты тоже будут скопированы.
Ответ: поверхностная копия создаёт новый объект и копирует его свойства первого уровня. Если свойство содержит ссылку на вложенный объект, копируется сама ссылка, а не содержимое вложенного объекта. Поэтому изменения становятся видны в обоих объектах.





5. Почему два объекта с одинаковым содержимым не равны по ===?
Потому что объекты в JavaScript сравниваются по ссылкам, а не по содержимому.
Пример:
const a = {
    name: 'Мышь',
    price: 790
};
const b = {
    name: 'Мышь',
    price: 790
};
console.log(a === b);
Результат:
false
Несмотря на одинаковое содержимое, объекты созданы отдельно.
Они занимают разные области памяти и имеют разные ссылки.
Но:
const c = a;
console.log(a === c);
Результат:
true
Потому что c получила ту же ссылку, что и a.
Ответ: оператор === сравнивает ссылки на объекты. Два объекта с одинаковыми свойствами не равны, если являются разными объектами в памяти.





6. Какие четыре шага выполняет оператор new?
Рассмотрим пример:
function Product(name, price) {
    this.name = name;
    this.price = price;
}
const mouse = new Product('Мышь', 790);
При выполнении new Product(...) происходят четыре основных действия.
Шаг 1. Создаётся новый пустой объект.
JavaScript создаёт объект, в который будут помещены свойства товара.
Шаг 2. Устанавливается прототип объекта.
Прототипом становится:
Product.prototype
Шаг 3. Вызывается функция-конструктор.
Внутри конструктора this указывает на созданный объект.
Поэтому:
this.name = name;
this.price = price;
Записывает свойства именно в него.
Шаг 4. Возвращается созданный объект.
Результат сохраняется в переменной mouse.
Теперь:
console.log(mouse);
Выведет объект товара.
Ответ: оператор new создаёт пустой объект, устанавливает его прототип, вызывает конструктор с новым объектом в качестве this и возвращает созданный объект.





7. Что такое прототип и как движок ищет свойство по цепочке прототипов?
Прототип — это объект, с которым другой объект связан специальной внутренней ссылкой.
Благодаря прототипам объекты могут наследовать свойства и методы друг от друга.
Пример:
const productMethods = {
    describe() {
        return 'Товар: ' + this.name;
    }
};
const mouse = Object.create(productMethods);
mouse.name = 'Мышь';
console.log(mouse.describe());
Результат:
Товар: Мышь
У объекта mouse нет собственного метода describe.
Но он есть в productMethods.
Когда JavaScript выполняет:
mouse.describe()
поиск происходит следующим образом:
1. Проверяется сам объект mouse.
2. Если свойства нет, проверяется его прототип productMethods.
3. Если и там нет, поиск продолжается дальше по цепочке.
4. Если свойство не найдено до конца цепочки, возвращается undefined.
Обычно цепочка заканчивается на Object.prototype, после которого находится null.
Ответ: прототип — объект, от которого другой объект наследует свойства и методы. При обращении к свойству JavaScript сначала проверяет сам объект, затем последовательно проверяет его прототипы до нахождения свойства или достижения null.





8. Чем отличаются call, apply и bind?
Все три метода позволяют управлять значением this, но отличаются способом применения.
call() — немедленный вызов функции.
function describe(currency, suffix) {
    return `${this.name}: ${this.price} ${currency}${suffix}`;
}
const product = {
    name: 'Мышь',
    price: 790
};
console.log(describe.call(product, '₽', '!'));
Первым аргументом передаётся объект для this.
Остальные аргументы передаются через запятую.
Результат:
Мышь: 790 ₽!
apply() — тоже немедленный вызов функции.
console.log(describe.apply(product, ['$', '?']));
Разница: аргументы передаются массивом.
Результат:
Мышь: 790 $?
bind() — создание новой функции.
const boundDescribe = describe.bind(product);
console.log(boundDescribe('₽', '!'));
В отличие от двух предыдущих методов, bind() не вызывает функцию сразу.
Он возвращает новую функцию с привязанным this.
Ответ:
Метод	Что делает	Передача аргументов
call()	Вызывает функцию	Через запятую
apply()	Вызывает функцию	Массивом
bind()	Создаёт новую функцию	При последующем вызове





9. Какие флаги есть у свойства и что делает каждый из них?
У обычного свойства объекта есть три основных флага.
1. writable
Определяет, можно ли изменять значение свойства.
const product = {};
Object.defineProperty(product, 'price', {
    value: 790,
    writable: false
});
Теперь:
product.price = 1000;
В строгом режиме вызовет ошибку.
2. enumerable
Определяет, участвует ли свойство в перечислении.
Например, в:
Object.keys(product);
Свойства с enumerable: false не попадут.
3. configurable
Определяет, можно ли удалять свойство и изменять его конфигурацию.
Например:
Object.defineProperty(product, 'id', {
    value: 1,
    configurable: false
});
Такое свойство нельзя удалить обычным оператором delete.
Ответ: writable отвечает за изменение значения, enumerable — за участие в переборе свойств, configurable — за возможность удаления и перенастройки свойства.
Важно: при создании свойства обычным присваиванием эти три флага обычно устанавливаются в true. При Object.defineProperty() неуказанные флаги по умолчанию имеют значение false.





10. Чем Object.freeze отличается от const? Почему заморозка поверхностная?
const и Object.freeze() решают разные задачи.
const запрещает переназначать переменную.
Пример:
const product = {
    name: 'Мышь',
    price: 790
};
Так нельзя:
product = {};
Потому что переменная объявлена через const.
Но так можно:
product.price = 850;
Потому что сам объект остаётся изменяемым.
Object.freeze() замораживает свойства объекта.
const product = Object.freeze({
    name: 'Мышь',
    price: 790
});
Теперь нельзя:
- изменять существующие свойства;
- добавлять новые свойства;
- удалять существующие свойства.
В строгом режиме попытка изменить замороженный объект вызовет ошибку.
Почему заморозка поверхностная?

Рассмотрим:
const settings = Object.freeze({
    currency: '₽',
    limits: {
        maxItems: 10
    }
});
Основной объект заморожен, но вложенный объект limits — нет.
Поэтому:
settings.limits.maxItems = 999;
Всё ещё сработает.
Причина: Object.freeze() замораживает только переданный объект и не переходит автоматически внутрь вложенных объектов.
Чтобы заморозить все уровни, нужна рекурсивная функция deepFreeze(), которую мы написали в задании 8.
Ответ: const запрещает переназначать переменную, но не запрещает изменять её объект. Object.freeze() запрещает менять свойства самого объекта. Заморозка поверхностная, потому что вложенные объекты остаются самостоятельными объектами и автоматически не замораживаются.
